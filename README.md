# Kubernetes alert triage with a small fine-tuned model

Fine-tune Qwen3-1.7B with LoRA to name the fault behind a Kubernetes alert, then serve it inside
the cluster with llama.cpp. The dataset is generated by injecting faults into a local kind cluster
and labelling every alert with the fault that caused it.

| Model, 124 held-out alerts | Accuracy | Macro F1 |
| --- | --- | --- |
| Qwen3-1.7B + LoRA (302 training alerts) | 79.8% | 0.793 |
| Claude Opus 5 | 67.7% | 0.670 |
| Gemini 3.5 Flash-Lite | 60.5% | 0.557 |
| Qwen3-1.7B, untuned | 10.5% | 0.063 |

## Layout

```
harness/     kind cluster, kube-prometheus-stack values, alert rules, demo app, capture and collection
faults/      fault catalogue and injectors, each with its own undo
eval/        prompt, API-model scoring, grouped train/test split
models/      training export, LoRA training, merge and quantization scoring (Colab)
serve/       llama-server deployment and the Alertmanager webhook service
results/     scores and per-alert answers
diagrams/    figures, drawn from results/
```

## Pipeline

1. **Cluster and data.** Follow [harness/RUN.md](harness/RUN.md) to create the cluster and collect
   labelled alerts into `data/alerts.jsonl`, or run `harness/collect.py` to collect until every
   class reaches a target.
2. **Split.** `.venv/bin/python eval/make_grouped_split.py` writes `results/split-grouped.json`,
   stratified by class with each injection window on one side only.
3. **Export.** `python3 models/export_training.py` writes `models/data/train.jsonl` and `eval.jsonl`
   in chat format.
4. **Train.** Upload both files and `eval/baseline.py` to a Colab T4 and run `models/train_colab.py`. It scores the base
   model, trains the LoRA adapter, scores again and writes a q8_0 GGUF.
5. **Compare.** `.venv/bin/python eval/baseline.py --model anthropic/claude-opus-5` scores an API
   model on the same split through OpenRouter (`OPENROUTER_API_KEY` in `.env`).
6. **Check the packaging.** `models/score_merged.py` and `models/score_quantizations.py` score the
   merged model and each GGUF quantization.
7. **Serve.** Build the service image from the repo root with
   `docker build -f serve/Dockerfile -t triage:dev .`, apply `serve/manifests.yaml`, copy the GGUF onto the model volume and
   point Alertmanager's `triage` receiver at the service.

## Requirements

Docker (or Colima), kind, kubectl, helm and Python 3.11+ for the harness. A free Colab T4 for
training and scoring.
